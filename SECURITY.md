# Security and privacy

Node-Sight launches the system OpenSSH client and streams a read-only POSIX collector into that SSH session. It does not install a service on the server, expose a web endpoint or send analytics.

## Credential handling

Connection preferences are stored under `%LOCALAPPDATA%\NodeSight`. Passwords are absent from the INI and source; optional password authentication uses Windows Credential Manager and the sibling askpass helper. Normal OpenSSH keys and `ssh-agent` remain available. The helper writes the secret only to its inherited askpass pipe and scrubs its temporary buffers on exit.

Credential protection has the boundaries of the logged-in Windows account: this app does not protect secrets against a compromised account or administrator. Use a dedicated least-privilege SSH account where practical.

## Host identity

`StrictHostKeyChecking=accept-new` trusts a previously unseen host key on first use and refuses a changed known key. It does not verify the first fingerprint out of band. For stricter first-use assurance, verify the host fingerprint through a trusted channel and populate your normal OpenSSH `known_hosts` before connecting. Node-Sight does not disable host-key checks or overwrite changed keys.

## Sharing data safely

The repository contains reserved example hostnames and synthetic documentation images. Your real settings, key paths, private keys and runtime exports belong outside version control. Live previews and SSH error text can contain connection identities; inspect them before sharing. Benchmark reports generated by `tools/measure.ps1` omit addresses, machine names, credentials and process IDs.

## Reporting a vulnerability

Use the repository's private vulnerability reporting feature if it is available, or contact the repository owner privately. Do not post passwords, keys, tokens or a real server address in a public issue. This project has no guaranteed response-time policy.
