# Security and privacy

Node-Sight launches the system OpenSSH client and streams a read-only POSIX collector into that SSH session. It does not install a service on the server, expose a web endpoint or send analytics.

## Credential handling

Windows preferences are stored under `%LOCALAPPDATA%\NodeSight`; Linux uses `$XDG_CONFIG_HOME/node-sight` or `~/.config/node-sight`. Passwords are absent from the INI and source. Windows optional password authentication uses Credential Manager and the sibling askpass helper. Linux currently uses keys/`ssh-agent`, not the Windows password helper. The helper writes a secret only to its inherited askpass pipe and scrubs temporary buffers on exit.

Credential protection has the boundaries of the logged-in Windows account: this app does not protect secrets against a compromised account or administrator. Use a dedicated least-privilege SSH account where practical.

Windows limits inherited SSH handles to each profile's own streams. Linux uses close-on-exec pipes and independent process groups. This isolates session lifetimes; it is not a sandbox for a compromised system SSH executable or desktop account.

## Host identity

`StrictHostKeyChecking=accept-new` trusts a previously unseen host key on first use and refuses a changed known key. It does not verify the first fingerprint out of band. For stricter first-use assurance, verify the host fingerprint through a trusted channel and populate your normal OpenSSH `known_hosts` before connecting. Node-Sight does not disable host-key checks or overwrite changed keys.

## Sharing data safely

The repository contains reserved example hostnames and synthetic documentation images. Your real settings, key paths, private keys and runtime exports belong outside version control. Desktop captures and SSH error text can contain connection identities; inspect them before sharing. Benchmark reports generated by `tools/measure.ps1` omit addresses, machine names, credentials and process IDs.

Optional logs write to the selected folder, with bounded rotation. They contain profile IDs, friendly aliases, resource measurements and UTC times. Destinations, SSH users and key paths are not automatically included, but an alias may itself identify a private system. A selected network/share folder may be readable by others according to its filesystem permissions. Inspect logs before sharing; normal buffering does not provide a transactional audit trail after forced termination.

## Reporting a vulnerability

Use the repository's private vulnerability reporting feature if it is available, or contact the repository owner privately. Do not post passwords, keys, tokens or a real server address in a public issue. This project has no guaranteed response-time policy.
